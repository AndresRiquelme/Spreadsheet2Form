# Contributing to Spreadsheet2Form

First of all, thank you for your interest in contributing to Spreadsheet2Form!

The goal of this project is to provide educators with a reliable, transparent, and freely available tool for safely transferring grade data from spreadsheets to web forms. Contributions of all kinds are welcome, including code improvements, documentation, bug reports, testing, and feature suggestions.

---

# Project Philosophy

Spreadsheet2Form is developed under the GNU General Public License v3.0 (GPL v3).

The project is intended to remain free software that benefits educators, students, and educational institutions. All contributions should support the project's goals of openness, reliability, maintainability, and data integrity.

---

# Ways to Contribute

You can contribute by:

* Reporting bugs.
* Suggesting new features.
* Improving documentation.
* Testing new releases.
* Improving the user interface.
* Supporting additional grading systems.
* Improving code quality or performance.

Every contribution, large or small, is appreciated.

---
# Supporting Additional Institutions

One of the most valuable ways to contribute to Spreadsheet2Form is by helping extend support to additional educational institutions.

If your university uses a different web-based grading system, you can contribute by providing information about its grading page.

Useful information includes:

* The URL of the grading page (if publicly accessible).
* Screenshots of the grading interface (with all personal information removed).
* A description of how grades are entered.
* The HTML structure of the grading table or form, if available.
* Sample clipboard data exported from your preferred spreadsheet application.

In most cases, this information is sufficient to implement support for a new institution without requiring contributors to modify the source code.

The long-term goal of Spreadsheet2Form is to support multiple educational institutions through configurable institution profiles while maintaining a common and reliable validation workflow.

# Reporting Bugs

When reporting a bug, please include:

* Operating system.
* Firefox version.
* Spreadsheet application used (LibreOffice Calc, Microsoft Excel, Google Sheets, etc.).
* Description of the problem.
* Steps required to reproduce the issue.
* Expected behavior.
* Actual behavior.
* Screenshots, if applicable.

Providing detailed information helps reproduce and resolve issues more quickly.

---

# Suggesting Features

Feature requests are welcome.

When proposing a new feature, please explain:

* The problem you are trying to solve.
* Why the feature would benefit users.
* Any ideas you have for its implementation.

Discussion before implementation is encouraged.

---

# Development Guidelines

The project follows a modular architecture.

Whenever possible:

* Keep modules focused on a single responsibility.
* Prefer readability over clever code.
* Avoid unnecessary dependencies.
* Write clear comments where appropriate.
* Preserve backward compatibility whenever practical.

All new functionality should include appropriate validation and should not compromise the safety of grade transfers.

---

# Coding Style

General guidelines:

* Use meaningful variable and function names.
* Prefer descriptive comments over complex code.
* Keep functions reasonably small.
* Maintain consistent formatting throughout the project.
* Use UTF-8 encoding for all source files.

Consistency is more important than personal coding preferences.

---

# Pull Requests

Before submitting a pull request:

* Ensure the extension works correctly.
* Test both sequential mode and Student ID mode when applicable.
* Update documentation if behavior changes.
* Update the CHANGELOG when introducing user-visible changes.

Small, focused pull requests are preferred over large unrelated changes.

---

# Code of Conduct

Contributors are expected to communicate respectfully and constructively.

The purpose of this project is to support education through open collaboration.
